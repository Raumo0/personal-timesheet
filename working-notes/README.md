# Working Agreement Notes

Use a local note only after the human unambiguously approves part of an ongoing, materially unresolved discussion. Active notes are local-only and persist in the repository's primary checkout; `README.md` and `TEMPLATE.md` are the only tracked files here.

Linked worktrees share this primary-checkout directory. Do not copy an active note into a feature worktree. A note mirrors the conversation's language and terminology.

Record approved agreements in chronological order. Before changing an existing agreement, show the exact entry, explain and preview the change, then obtain explicit human approval. Create a new `amends` or `supersedes` agreement for material changes.

When discussion moves to planning, implementation, durable transfer, or closeout, announce a partial handoff or full closeout with the affected agreements, then update the same note's mutable `Reconciliation` section. Keep it before append-only `Agreements`; do not create a companion file. Map agreements and local actions many-to-many through the Agreement Ledger, Action Register, and Coverage Matrix. A partial mapping names its exact contribution. A newly appended agreement without mapped work receives only a `pending` ledger row.

Showing an agreement does not authorize implementation. Partial handoff leaves unrelated agreements active. Full closeout requires every agreement to be verified against durable evidence or explicitly excluded with a reason. Delete a note only after a separate explicit Human Gate, with its path, durable destinations, possible lost information, and safety reason shown first.

See [the canonical process](../processes/progressive-working-agreement-notes.md) for the complete rules.
